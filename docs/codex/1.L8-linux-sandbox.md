## Goal

On Linux (x86_64 and aarch64), `nc_exec::sandbox::spawn` starts `nc-exec-worker` with **every** layer below applied, or returns `SandboxError`. There is no partial mode and no weaker fallback (invariant 3). Keep the public API exactly the same as on Windows:

- `SandboxSpec`, `SandboxedChild` with `spawn`, `resume`, `wait`, `events`, `kill`, `timings`, `teardown` and `peak_memory_bytes`;
- `sweep_leftovers`;
- `PROFILE_PREFIX`;
- `SandboxEvent::{MemoryLimit, ProcessLimit}`.

Keep `unsupported.rs` for the other non-Windows targets, such as macOS.

## Layers

### 1.L8: namespaces, no network, minimal filesystem

- Run without root, using unprivileged user namespaces: a new user, mount, PID, network, IPC, UTS and cgroup namespace. Map the calling user to a single uid/gid inside.
- The network namespace has no interfaces apart from a loopback that stays down. The worker must not be able to open any socket that reaches outside.
- Mounts:
  - pivot_root into a fresh tmpfs;
  - bind-mount only the worker binary and the dynamic loader/libs it needs, read-only (or link the worker statically if that is simpler and say so);
  - a fresh /proc for the new PID namespace;
  - no /dev apart from null, zero and urandom if they are needed;
  - no home, no /etc and no host paths.
- Set `PR_SET_NO_NEW_PRIVS`, drop every capability, close all fds except the three pipes, clear the environment, and set rlimits (`RLIMIT_NOFILE`, `RLIMIT_CORE`=0, `RLIMIT_FSIZE`).
- `resume()`: the child waits on a sync pipe until `resume()` is called, matching the Windows suspended-start semantics.
- If user namespaces are disabled (sysctl, AppArmor `apparmor_restrict_unprivileged_userns`), return a clear `SandboxError { step: "userns", .. }`. Do not fall back.

### 1.L9: seccomp

- Use an allow-list seccomp-bpf filter with default action KILL_PROCESS, or ERRNO with a test proving it is equivalent. Allow only the syscalls the worker needs for Wasmtime execution and its stdin/stdout IPC.
- Deny socket, connect, execve after start, ptrace, mount, unshare, setns, bpf, perf_event_open, keyctl, userfaultfd, io_uring, process_vm_* and clone with new-namespace flags.
- Build the filter for x86_64 and aarch64 (check `AUDIT_ARCH`). Prefer a well-reviewed crate such as `seccompiler` (check its licence against `deny.toml`) over a hand-written BPF filter.
- Map a seccomp kill of a forbidden spawn or exec attempt to `SandboxEvent::ProcessLimit` where it can be detected.

### 1.L10: cgroup v2 limits and teardown

- Create a cgroup under the user's delegated cgroup v2 subtree, using the systemd user slice or `$XDG_RUNTIME_DIR`-delegated scope. Name it `PROFILE_PREFIX` + a random id.
- Set limits:
  - `memory.max` = `spec.process_memory_bytes`, with swap at 0;
  - `pids.max` small, so a fork bomb hits it;
  - `cpu.max` set to a sensible share.
- Report `memory.events` oom_kill as `SandboxEvent::MemoryLimit`, and read `memory.peak` (or a polled maximum) for `peak_memory_bytes`.
- If no delegated cgroup v2 is available, return `SandboxError { step: "cgroup", .. }`. Do not fall back.
- `teardown()` kills everything in the cgroup (`cgroup.kill`), waits, removes the cgroup and returns the time it took. It must run on every path: success, Stop, timeout, crash and drop (invariant 4).
- `sweep_leftovers()` removes stale `PROFILE_PREFIX` cgroups left by a crashed agent and returns how many it removed.
- `kill()` must stop the whole tree in well under 1 s (invariant 5).

## Tests

These are the acceptance criteria. Run every one on a real Linux kernel: your Linux environment, a Docker container started with the needed `--security-opt` options (state exactly which), or WSL2. Record the real output.

- **Containment.** Port the existing Windows malicious-job tests (endless loop, memory growth, huge output) and make them pass on Linux. Where they are `#[cfg(windows)]`, generalise them.
- **New Linux escape tests**, each run inside the worker or with a probe binary under the same sandbox (see `examples/sandbox_probe` on Windows). Each test must show that one of these is blocked:
  - opening a TCP or UDP socket to an outside address;
  - reading `/etc/passwd` and the user's home directory;
  - writing outside tmpfs;
  - fork bomb (pids.max reached, reported as an event);
  - `execve` of `/bin/sh`;
  - ptrace of the parent;
  - unshare or mount;
  - memory above the cap (MemoryLimit event, the process is killed).
- **Lifecycle.**
  - `kill()` takes under 1 s with grandchildren present.
  - After `teardown()` no process and no cgroup is left.
  - `sweep_leftovers()` removes a deliberately leaked cgroup.
  - Dropping a `SandboxedChild` without calling teardown still cleans up.
- **Refusal.** With user namespaces or cgroup delegation unavailable (simulate it with an env or test hook that is compiled only for tests), spawn returns SandboxError and nothing runs.
- **CI.** Add the Linux sandbox test step to the ubuntu job in `.github/workflows/`. If GitHub's ubuntu runners need `sysctl kernel.apparmor_restrict_unprivileged_userns=0` or a systemd-run delegated scope, set it up in the workflow and explain why.
- **Workspace checks** in `core/`, all green:
  - `cargo fmt --check`;
  - `cargo clippy --all-targets -- -D warnings` on Linux and on Windows (the Windows build must still compile and its tests must still pass);
  - `cargo test`;
  - `cargo deny check`.
