## Goal (G7b)

A per-machine installer that a laptop owner double-clicks, which:

1. Installs `nc-agent.exe`, `nc-exec-worker.exe` and `nc.exe` into `%ProgramFiles%\Network Connector\`
   (read-only for users). The worker folder must be readable and executable by `ALL APPLICATION PACKAGES`
   (and `ALL RESTRICTED APPLICATION PACKAGES` only if the AppContainer sandbox needs it — check
   `core/crates/nc-exec/src/sandbox/windows.rs`, `grant_appcontainer_read`) and writable by nobody but
   Administrators/SYSTEM/TrustedInstaller.
2. Creates the data dir under `%ProgramData%\Network Connector\` with the exact ACL `service.rs` expects
   (or calls `nc-agent service install`, if that is what does it — prefer reusing the 1.L12 code path over
   re-implementing ACLs in the installer).
3. Registers and starts the `nc-agent` service as `NT SERVICE\nc-agent`, with the restart policy from 1.L12.
4. Does NOT enrol the device or start helping by itself. The owner still gives consent in the app or with `nc`
   (invariant: nothing runs jobs without explicit owner consent). No listening socket is opened by default
   (invariant 7).
5. Uninstall stops and removes the service, removes program files, and asks (or has a documented option)
   whether to keep `%ProgramData%\Network Connector\` (identity and history). Upgrade in place keeps the data
   dir and the device identity.

Pick WiX v4/v5 MSI (preferred: per-machine, works with service install/ACL custom actions, fits signed
updates) or MSIX; explain the choice. Licence of the toolchain must be OK for CI use.

## Signing (invariant 9)

- Authenticode-sign the three exes and the MSI with `signtool` in CI **only when** signing secrets exist
  (`WINDOWS_CERT_PFX_BASE64`, `WINDOWS_CERT_PASSWORD` as GitHub secrets). Without them, CI builds an unsigned
  MSI clearly named `*-unsigned.msi` and the job still passes. Never print the secrets; never commit a
  certificate or key.
- Use an RFC 3161 timestamp server.
- Document in `packaging/windows/README.md` how the owner gets a code-signing certificate and adds the secrets.

## Tests (real results)

- CI: the packaging job builds release binaries, builds the MSI, and on the `windows-latest` runner (which is
  elevated) installs it silently (`msiexec /i ... /qn`), then checks:
  - service `nc-agent` exists, runs as `NT SERVICE\nc-agent`, reaches Running;
  - program folder ACL: users cannot write; `ALL APPLICATION PACKAGES` has read+execute on the worker;
  - data dir ACL matches what `service.rs` sets;
  - Stop of the service finishes in under 1 s (invariant 5);
  - upgrade: install a second build with a higher version; the data dir and device identity file are kept;
  - uninstall (`msiexec /x ... /qn`): service gone, program folder gone, data dir handled as documented.
  Reuse checks from `infra/service-test.ps1` where you can rather than duplicating them.
- Locally: say what you ran. If you could not run an elevated install locally, say so; the CI run is the
  required proof.
